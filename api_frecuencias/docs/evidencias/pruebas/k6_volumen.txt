5) Lectura
   - Las consultas paginadas sobre las tablas de resultados cumplen RNF-002 con el volumen de un año: p95 627,5 ms con 50 usuarios concurrentes y 0 % de errores; en frío, la primera petición de cada colección tarda menos de 100 ms (17 de las 22 rutas medidas).
   - GET /api/v1/segmentos/estadisticas NO cumple: agrega en cada petición la tabla timbradas_segmentos de la réplica (sin caché), 8,8 s en frío y 11,9 s en caliente; con idruta, 2,3 a 2,9 s. Arreglo propuesto: caché con tiempo de vida (como los catálogos) o una agregación materializada que el ciclo refresque.
   - GET /api/v1/catalogos/segmentos tarda 5,0 s solo la primera vez (arma la geometría); después, la caché lo deja en 65 ms.
   - Las exportaciones CSV completas (3.348 predicciones, 8.988 alertas) tardan 3,4 a 5,2 s: son descargas del conjunto entero, no consultas paginadas; quedan fuera de RNF-002 y se documentan aquí.

Reproducir (desde EntregaFinal/api_frecuencias, con la base local arriba):
   python scripts/sembrar_volumen.py --base-datos ai_frecuencias_volumen --plantilla <base con ejecuciones reales> --ejecuciones 365 --recrear
   (API apuntando a esa base en :8507)   docker run --rm -e BASE=http://host.docker.internal:8507 -e SOBUSA_API_KEY -e MIN_PREDICCIONES=3300 -e MIN_ALERTAS=8000 -v "$PWD/k6:/scripts" grafana/k6:1.4.2 run /scripts/consultas.js   (los mínimos hacen que k6 se niegue a medir una base más pequeña)
   la prueba en frío, igual con /scripts/en_frio.js, justo después de arrancar la API (INCLUIR_PLAN=1 agrega /recommendations/plan y /respuesta).
