|---|---|---|---|
| Comprensión del problema (10 %) | Informe; README de la entrega («no quitar buses, cambiarlos de hora»); visita a Sobusa | Cumple | La API responde las cuatro preguntas de §1. |
| Calidad de datos (10 %) | Informe (validación de los datos, días sin GPS al cierre de cada mes); API `calidad.py`; partición cronológica | Cumple | Hay seis dimensiones con errores por lote, fila y causa (RF-004). La no fuga temporal está documentada en el informe y en `variables.py`: el día D usa datos hasta D−7. |
| Modelo predictivo (20 %) | Informe y Cuaderno: WAPE 20,04 % → 13,62 %, intervalos y bootstrap pareado; API con P10/P90 | Cumple | El modelo de la API supera la línea base: WAPE de prueba de 15,07 % frente a 21,18 % de B1 (manifiesto). |
| Optimización y alertas (20 %) | MILP D5 (Dash, Informe); API `recomendar` con viabilidad; alertas ALT-001 a ALT-010 | Parcial | Recomendaciones y alertas funcionan de punta a punta. ALT-005 a 008 solo se prueban en las unitarias (RF-009). El saldo económico depende de la elasticidad β = 0,70 (0,55-0,90): de −2.825 a +1.600 M COP al año; por eso el piloto. |
| Integración y rendimiento (15 %) | `docs/integracion_postgresql.md`; adaptador de solo lectura; marca de agua; `rendimiento.txt` | Parcial | El p95 y la ingesta de más de 100.000 filas están medidos en local. Falta una prueba sobre una réplica real y una prueba de carga concurrente. |
| Ingeniería de software (15 %) | API FastAPI + PostgreSQL + Alembic + pytest + Docker | Cumple | 147 pruebas, cobertura del 91 %, bandit 0 y Docker probado. SonarQube sigue pendiente (RNF-013). |
| Presentación y adopción (10 %) | `PLAN_EVOLUCION.md`; App; piloto de ocho semanas del informe | Parcial | Falta el video de 5 minutos. |
